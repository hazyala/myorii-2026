# macOS DMG 배포와 첫 실행 준비

## 빌드

프로젝트의 가상 환경에서 `python scripts/build_dmg.py`를 실행한다. 검은 묘리 원본(`assets/characters/myorii_profile.png`)으로 ICNS를 만들고 PyInstaller로 Python·Qt·인증서·리소스를 포함한 앱을 빌드한다. `dist/Myorii-macOS-arm64.dmg`와 SHA-256 파일이 생성된다. Intel Mac에서는 해당 아키텍처의 Python과 의존성으로 별도 빌드하며 파일명은 x86_64가 된다. `dist/`의 중간 빌드 결과는 Git에 넣지 않는다. 배포할 DMG와 체크섬은 `releases/`에 복사해 버전 관리한다.

DMG에는 Myorii.app, Applications 바로가기, 그림이 포함된 `설치 안내.pdf`가 들어간다. 웹 다운로드 링크로 배포할 수 있으며 로컬 추론용 서버를 운영할 필요는 없다. 현재 결과물은 ad-hoc 서명만 있는 배포본으로 Developer ID 서명·공증은 포함하지 않는다. Gatekeeper를 해제하거나 다운로드 격리 속성을 제거하는 동작은 없다. 다른 Mac의 첫 실행 허용은 사용자가 macOS 안내에 따라 결정해야 한다.

## 첫 실행

앱은 로컬 제공자의 선택 모델을 확인한다. 기본값은 `qwen3-vl:4b-instruct`(약 3.3GB)다. 서버가 응답하고 모델이 있으면 바로 메인 화면을 연다. 준비가 필요하면 검은 묘리 이미지, 필요한 다운로드 안내, 시작·나중에·취소 버튼을 표시한다. API 제공자가 설정되어 있으면 로컬 준비를 건너뛴다.

시작 버튼 이후 진행 순서:

1. 기존 Ollama 서버, `/Applications/Ollama.app`, `~/Applications/Ollama.app`, PATH의 CLI를 확인한다.
2. 설치가 없으면 공식 HTTPS 주소에서 DMG를 임시 다운로드한다. 앱의 Apple 서명과 Ollama 배포자 Team ID를 검사한다. 실패하면 실행하거나 설치하지 않는다.
3. 검증된 앱을 사용자 `~/Applications/Ollama.app`에 임시 복사 후 이동한다. 기존 설치를 덮어쓰지 않는다. 디스크 이미지는 해제하고 임시 파일을 정리한다.
4. Ollama 앱을 실행하고 응답을 기다린다. macOS 실행 승인 창은 사용자에게 안내한다. CLI 전용 설치는 `serve`를 실행한다.
5. 모델이 없으면 `/api/pull` 스트림으로 다운로드량과 레이어 진행률을 표시한다. 성공 이벤트와 실제 모델 목록을 모두 확인한다.
6. 모델을 실제 로딩해 메모리·실행 오류를 확인한 뒤 메인 화면으로 이동한다.

실패하면 오류와 재시도를 표시한다. 취소는 읽기·하위 프로세스 경계에서 처리하며 다운로드 연결은 최대 30초, 모델 로딩 연결은 최대 120초 기다릴 수 있다. Ollama 모델의 부분 다운로드는 재시도에 재사용한다. 취소 시 기존 설치·모델을 삭제하지 않는다. API 사용 / 나중에는 준비를 생략하고 앱 설정에서 제공자를 선택할 수 있게 한다. 로컬 준비가 안 된 상태로 다시 실행하면 안내가 다시 나온다.

## 검증 범위

2026-10-15: 자동 회귀 테스트 81개 통과. 기존 설치·모델 재사용, 미설치 흐름, 중단된 스트림, 다운로드 오류, 모델 로딩 실패, 취소 시 하위 프로세스 종료, 서명 불일치 시 설치 차단, 수 GB 진행률, UI 재시도를 검증했다.

실제 공식 Ollama DMG를 내려받아 별도 임시 폴더에 서명 검사·설치 후 CLI 실행을 확인했다. 사용자 설치와 모델은 변경하지 않았다. macOS 실제 준비 화면에서 검은 묘리 이미지·안내·버튼 배치를 확인했다. DMG 파일 무결성과 내부 앱 서명을 확인하고 DMG에서 복사한 앱 실행과 실제 채팅 응답을 확인했다.

별도 포트의 Ollama 서버와 빈 임시 모델 저장소에서 Qwen 약 3.3GB 전체 다운로드, 성공 이벤트, 모델 목록, 실제 모델 로딩을 확인했다. 테스트 서버를 종료하고 임시 저장소를 정리했다. 결과 요약은 `tests/results/dmg-setup-2026-10-15.json`에 기록한다.

이 Mac에서 검증한 빌드는 Apple Silicon용이다. 완전히 새 macOS 계정·별도 Mac의 Gatekeeper 승인 화면과 Intel 하드웨어는 별도 환경이 없어 검증하지 않았다.

### 첫 실행 위치 보완

2026-10-15 첫 실행에서 창이 묘리 아이콘 아래에 오지 않고 닫았다 열면 제자리를 찾는 문제를 수정했다. 메뉴바가 표시된 직후 0ms 타이머로 창을 열면 아직 아이콘 좌표가 비어 있어 화면 오른쪽 기본 위치를 사용했다. 이제 유효한 아이콘 좌표가 안정된 뒤 최초 창을 열고, 사용자가 먼저 클릭하면 자동 열기를 취소한다. 위치를 얻지 못하면 임의 위치에 열지 않는다. 앞서 배경 문제로 잘못 해석해 변경한 투명도·그림자는 원래 디자인으로 복원했다.

첫 네이티브 창 생성 때 Cocoa가 세로 위치를 보정하는 동작도 있어 `show()` 직후 같은 앵커 좌표를 다시 적용한다. 실제 macOS 검증에서 아이콘 `[990, 0, 38, 29]`에 대해 첫 창 위치 `[793, 41]`가 예상 좌표와 일치했다. `PYTHONPATH=. .venv/bin/python tests/manual_startup_position.py`로 사용자 DB를 변경하지 않고 네이티브 첫 표시 좌표를 재검증할 수 있다. 최신 자동 회귀 테스트는 85개 통과했다.

### macOS 버전 조회 패키징 수정 (2026-10-15)

OS 27에서도 'macOS 14 이상 필요'가 나타난 원인은 동적으로 읽는 표준 platform 모듈의 plistlib 의존성이 번들에 누락되어 버전 조회가 빈 문자열을 반환했기 때문이다. 이 빈 값을 0으로 간주하던 검사도 함께 수정했다.

이제 plistlib를 명시적으로 포함해 시스템 ProductVersion을 읽고, 실패하면 호환 버전 모드를 끈 `/usr/bin/sw_vers -productVersion`을 사용한다. 둘 다 실패하면 버전 확인 실패로 안내하며 구버전이라고 판단하지 않는다. 빌드 과정은 완성된 Myorii.app의 `--check-install-environment`를 실행해 실제 macOS 버전과 일치하는지 검증한 뒤에만 DMG를 생성한다. 14·15·26·27 버전, 실제 구버전, 조회 실패를 포함한 전체 자동 테스트 89개가 통과했다.

### 그림 설치 안내

텍스트 안내를 2페이지 PDF로 교체했다. 사용자가 제공한 설치 창과 보안 설정 스크린샷 위에 벡터 화살표·강조 테두리·순서 번호를 표시한다. 원본 이미지는 `packaging/macos/guide-images/`, 생성 코드는 `scripts/build_install_guide.py`, 배포 PDF는 `output/pdf/Myorii-install-guide.pdf`에 둔다. PDF를 수정할 때는 reportlab이 있는 Python으로 생성 스크립트를 실행하고 두 페이지를 렌더링해 확인한 다음 DMG를 빌드한다. 일반 DMG 빌드는 저장된 PDF를 사용하므로 reportlab이 필요하지 않다.

## v1.0 배포

기능 브랜치를 dev에 통합하고 dev → main PR을 병합한 뒤, main의 최종 배포 커밋에 `v1.0` 태그를 생성한다. dev에는 배포 태그를 달지 않는다. README의 DMG 링크는 이 태그의 파일을 가리켜 이후 개발 변경과 무관하게 같은 배포본을 내려받는다. 앱 설정에는 v1.0, macOS 번들에는 1.0.0을 표시한다. 서명·공증 및 별도 Mac 검증 범위는 위와 동일하다.
